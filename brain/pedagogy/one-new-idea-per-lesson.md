**Rule.** A lesson introduces exactly one new idea. Everything else in it is scaffolding for that idea — a prior concept reused, an analogy, a misconception cleared — but only one thing in the lesson is being met for the first time.

**Why our learner needs it.** The spine persona is a salesperson with no technical background. For that reader, a "small" second concept is not small: it competes for the same working memory the first concept needs to land, and the usual result is that neither sticks. One idea per lesson is how a beginner course stays passable rather than merely complete.

**How we apply it.** Name the single idea in one sentence before writing the lesson. If the draft cannot be summarized as "this lesson teaches X", it is teaching two things and must be split. A twenty-lesson course therefore carries at most twenty new ideas, which is a feature: it forces the curriculum to choose.

**The misconception this pre-empts (in us, the authors).** More coverage feels like more value, so a lesson quietly grows a second and third point, each individually defensible. Sprawl never feels like sprawl; it feels like thoroughness. The cap is the defense against our own instinct to add.

**What "one idea" is not.** It is not one fact. A lesson may state several facts if they all serve the single idea — the bank-teller analogy, the view-source example, and the trust boundary can all live in one lesson because they teach one thing. The test is the summary sentence, not the fact count.

**How it shows up in assessment.** Each Lecture contributes one scenario question to its section's Quiz, and that question tests the Lecture's single idea, not the supporting facts. The "one idea" rule binds **per question**, not per Quiz: a section Quiz may hold several questions, each testing one earlier Lecture's idea. If a single Lecture needs two questions to cover it, that Lecture had two ideas.
